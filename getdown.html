配ったあとに、
直せるようにする。

お店のパソコン200台に入れたアプリに、バグが見つかった。直したものを届けるために、200台ぶん出張する？ それとも、アプリ自身に取りに行かせる？ Getdown は後者を引き受ける、小さな門番です。本体より先に起動して、変わったファイルだけ取ってきてから、本体を立ち上げます。

アイコンをダブルクリックしてから、画面が出るまで——

  1. ダブルクリックいま 利用者は、いつもどおりアイコンを押しただけ
  2. 最初に動くのは本体ではない
  3. ランチャー小さな門番 Getdown本体。数百KBの、ただの小さなプログラム
  4. サーバーを見に行く
  5. 見くらべるハッシュで照合 手元のファイルと、置いてある一覧を1つずつ比べる
  6. ちがうものだけ落とす
  7. 本体が起動いつも最新 更新が終わってから、アプリの画面が開く

やっていることは「起動前に、差分だけ入れ替える」。これが今日のいちばん大事なところ。

なんで、こんなものが要るの？

答えはシンプル。デスクトップアプリは、配ったら終わりだから。

Webサイトなら、悩まなくていい

Webサイトの直しは簡単です。サーバーのファイルを差し替えれば、次に見た人はもう新しいものを見ている。利用者は何もしなくていい。

ところがパソコンに入れるアプリは、利用者の手元にコピーが残ります。サーバーを直しても、手元のものは古いままです。

「更新してください」は、届かない

お知らせを出しても、全員が読んで、全員が入れ直してくれることはありません。結果として、新旧のバージョンが同時に動く状態が生まれます。

サーバー側と噛み合わない古いアプリが1台でも残ると、問い合わせの原因になります。数が多いほど、原因の切り分けも難しくなります。

ブラウザから起動する道は、閉じた

かつては Java Web Start という、ブラウザのリンクからアプリを起動して自動更新する仕組みがありました。今はもう使えません。

その置きかえとして残ったのが、Getdownのようなランチャー方式です。ブラウザに頼らず、アプリ自身が更新を取りに行きます。

毎回どれだけ落とす？

ボタンで切りかえて、ダウンロードの量を見くらべてみよう。

1台あたりのダウンロード　80 MB

台数が増えると、どうなる？

アプリの大きさと台数を選ぶと、1回の更新で流れる通信量を計算します。

起動のたびに、やっていること

ダブルクリックから画面が出るまでの5つの場面。タップして開いてみよう。

ランチャーの仕事

登場するファイルは、2つだけ

仕組みの中心は、この2枚のテキストです。

getdown.txt — 何を、どこから、どう起動するか

人が書く設定ファイル。更新ファイルの置き場所（appbase）、読み込むjarの一覧、起動するクラス名などを並べます。

中身はただのテキスト。ここに書かれたURLを基準に、すべてのファイルの場所が決まります。

digest — ファイル一覧とハッシュ

付属のツールが自動で作る一覧表。どのファイルが、どんな中身なのかを、ハッシュ値で書き残しています。手元と見くらべる相手がこれです。

古い方式の digest.txt と、新しいハッシュを使う digest2.txt の2枚が置かれます。今のGetdownは新しいほうを優先して見ます。

サーバーは、ただの置き場でいい

配信側に特別なソフトは要りません。ファイルを置いた普通のWebサーバーがあれば動きます。

インストーラに入れて配るのは、ランチャーと、本物の設定ファイルの場所を書いた入口だけ。アプリ本体は入っていません。

クイズ：きみは何問わかる？

全5問。まちがえても大丈夫、答えのほうが面白い。

気をつけないと、あとで泣く

「起動のたびに自動で落として実行する」仕組みなので、そこが弱点にもなります。

  1. 配信は必ず https に。通信の途中で差し替えられたら、全台にそのまま配られます。自動で実行される仕組みだからこそ、経路の安全は必須です。
  2. 署名を使う。一覧表に署名を付けておけば、置き場が荒らされても、改ざんされたファイルを掴まされずにすみます。
  3. 更新の途中で切れても壊れないように。落とす途中で電源が落ちる、回線が切れる。検証に失敗したものは捨てて、次の起動でやり直す前提にしておきます。
  4. 戻す手順を決めておく。配ったあとに不具合が見つかったら、置き場のファイルを前のものに戻します。「戻したら全台がどうなるか」を先に一度試しておきます。
  5. Javaそのものの配布は、別問題。Getdownが更新するのはアプリのファイルです。動かすためのJavaをどう配って、どう上げるかは、別に決める必要があります。
  6. 起動時間が伸びることを見込む。毎回サーバーを見に行くので、ネットワークが遅い拠点では起動が遅くなります。オフライン時の挙動も確認しておきます。

ことばのミニ辞典

この先どこかで見かけたときのために。

ランチャー
本体より先に起動して、準備をしてからアプリを立ち上げる小さなプログラム。Getdownの正体はこれ。
appbase
更新ファイルが置いてあるURL。設定に書かれたすべてのファイル名は、この場所を基準に組み立てられる。
getdown.txt
人が書く設定ファイル。配布元のURL、読み込むjar、起動するクラスなどを書く。
digest
ファイルの一覧とハッシュ値を書いた表。手元と見くらべて、変わったものを見つけるために使う。
ハッシュ
ファイルの中身から計算した短い値。中身が1バイトでも違えば別の値になるので、同じかどうかの判定に使える。
Java Web Start
かつてブラウザ経由でJavaアプリを起動・更新していた仕組み。廃止されたことが、ランチャー方式が使われる背景になっている。
