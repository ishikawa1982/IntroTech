MCPのしくみ v3.0.0 ← 用語集トップ

AIは、外の道具を
借りて動いている。

「明日の予定を教えて」と聞くと、AIが答えを返してくる。でもAIは、きみの予定表を最初から知っているわけじゃない。裏側では、道具を借りにいくためのやりとりが起きている。その借り方の決まりごとが MCP だ。

「明日の予定を教えて」と聞いたときの、裏側のバケツリレー——

  1. きみ質問する 「明日の予定を教えて」
  2. たのむ
  3. AI考える役 カレンダーの道具が使えそうだ、と判断する
  4. 道具を借りる
  5. MCP共通の差し込み口 どのAIからでも同じ形で頼める窓口
  6. 取ってくる
  7. カレンダー本物のデータ 明日の予定がしまってある場所

AIが自分でカレンダーを開いているわけじゃない。お願いを出しているだけ、というのが今日いちばん大事なところ。

なんで、こんな決まりごとが必要なの？

答えはシンプル。つなぎ方がバラバラで、大変だったから。

むかしの充電ケーブルと同じ話

ひと昔前のケータイは、機種ごとに充電の差し込み口の形がちがった。友だちのケーブルは借りられないし、家じゅうにケーブルが増えていった。

今は USB Type-C にそろってきて、1本あればだいたい挿さる。MCPは、これをAIの世界でやろうという取り決め。

組み合わせの数が、こわい

AIが3種類、つなぎたいサービスが3種類あるとする。決まりがないと、その組み合わせぶんだけ専用のつなぎ役プログラムを作ることになる。3×3で9本。

AIが5種類、サービスが10種類になったら50本。作るのも大変だし、直すのはもっと大変になる。

まん中に「共通の口」を置く

それぞれが好きな形でつなぐのをやめて、まん中に共通の差し込み口をひとつ用意する。AI側は「MCPの口に挿す」だけ、サービス側も「MCPの口を用意する」だけでよくなる。

これで、あとから新しいサービスが増えても、AIのほうを作り直さなくてよくなった。

ケーブルの本数で見てみる

ボタンで切りかえて、線の数のちがいを見てみよう。

作るつなぎ役プログラム　9 本

数を変えると、どれくらい差がつく？

AIとサービスの数を選ぶと、必要な本数を計算する。増やすほど差が開くのが見どころ。

4つのステップを、開いて確かめる

それぞれの場面で「誰が何をしているか」をタップして開いてみよう。

「明日の予定を教えて」と聞いてから、答えが返るまで

MCPが差し出せる、3つのもの

サービス側に置く窓口を MCPサーバー と呼ぶ。渡せるものは大きく3種類。

ツール ＝ 手

実際に何かをする機能。予定を登録する、メールを送る、検索する。AIの手にあたる部分。

手なので、使うと現実が変わる。だからいちばん慎重にあつかわれる。

リソース ＝ 目

読み取るためのデータ。ファイルの中身、商品の一覧、記録された数値。

見るだけで、書きかえはしない。見せる範囲は人が決められる。

プロンプト ＝ メモ

「こういうときは、こう頼むとうまくいく」という定型の指示文。

よく使う手順をあらかじめ置いておける、ちょっとしたカンニングペーパー。

クイズ：きみは何問わかる？

全5問。まちがえても大丈夫、答えのほうが面白い。

勝手に動いたりしないの？

ここは大人もよく気にするところ。

  1. 触れる範囲は、あらかじめ決めておく。「カレンダーを読む」しか許していなければ、AIが予定を消すことはできない。
  2. 使う直前に、人に聞く。多くのAIアプリは、道具を使う前に「これ、やっていい？」と確認を出す。
  3. 記録が残る。いつ、どの道具を、何のために使ったかを後から確かめられる。
  4. 決まりがそろったから、見張りやすい。つなぎ方がバラバラだった頃より、どこまで許したかを人が把握しやすくなった。

ことばのミニ辞典

この先どこかで見かけたときのために。

プロトコル
機械どうしが会話するときの決まりごと。言葉づかいのルールブックのようなもの。MCPの「P」はこれ。
MCPホスト
AIが動いているアプリ本体。チャットの画面や、プログラムを書くための道具など。
MCPサーバー
サービス側に置く窓口。「うちではこの道具と、このデータが使えます」とAIに知らせる役。
オープンな規格
仕様が公開されていて、誰でも同じルールで作れる状態。MCPは2024年に Anthropic が公開した。

ほかの解説ページ

  • CI/CDのしくみ直したものを、こわがらずに届けるために。
  • WebSocketのしくみ「まだ？」と聞きに行かなくてよくなった日。
  • Flywayのしくみデータベースだけ、やり直しがきかない。
  • Getdownのしくみ配ったあとに、直せるようにする。
  • Angularのしくみ画面を、部品に切り分ける。
  • BIG-IPのしくみ入口を1つにして、裏を何台にでも。
  • Springのしくみ部品の組み立てを、任せてしまう。
  • Dockerのしくみ「私のPCでは動く」を、なくすために。
  • Kubernetesのしくみ落ちたら、勝手に起き上がる。

MCP（Model Context Protocol）を、たとえ話・図解・クイズでたどるやさしい解説ページです。技術の細かい仕様は、公開されている本家の仕様書をどうぞ。
