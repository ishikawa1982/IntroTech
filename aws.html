サーバーを、
買わずに借りる。

むかしは、サービスを1つ始めるのに機械を買うところからでした。見積もりを取り、届くのを待ち、置き場所と電源と回線を用意する。AWS は、その一式を「申し込んだら数分で使えて、要らなくなったら返せるもの」に変えました。返した瞬間から、お金もかからなくなります。

申し込みから、サービスが動きだすまで——

  1. 借りるいま 画面から「この大きさの機械を1台」と頼むと、数分で使える状態になる（EC2）
  2. 1台だと、落ちたら終わりなので
  3. 増やす台数を横に 同じものを何台か並べ、前に受付を置いて振り分ける（ELB）
  4. アプリの置き方も、箱で統一したくなって
  5. 任せる自動 コンテナを「どこに何個」だけ決めて、置き場所の世話は任せる（ECS）
  6. 消えて困るデータだけは、別あつかい
  7. 預ける壊れても残る データベースは専用の場所に置き、バックアップや故障時の切りかえも任せる（RDS）

今日おぼえて帰るのは、この4つの役どころだけで大丈夫。

なんで、こんなものが生まれたの？

答えはシンプル。機械を買うと、あとから変えられないから。

使う量は、始める前にはわからない

買うときは「どれくらい来るか」を先に決めなければいけません。小さく買えば足りなくなり、大きく買えば余ります。どちらに転んでも、当たることのほうが少ないのです。

当てにいった見積もりが外れると、次の機械が届くまでの数週間、打つ手がありません。

いちばん混む日に、大きさを合わせてしまう

年に数回のピークに耐えられるようそろえると、残りの364日は、そのほとんどが遊んでいます。電気代も置き場所代も、遊んでいるあいだも同じだけかかります。

「念のため多めに」は、買う世界ではずっと払い続ける約束になります。

だから、必要なときに必要なぶんだけ借りる

借りる形なら、混む日だけ台数を増やして、終わったら返せます。払うのは使ったぶんだけ。読みを外しても、あとから直せます。

クラウドのいちばんの利点は「安い」ことではなく、決め打ちしなくてよくなることです。

よくある形は、この4つの重なり

名前は多いけれど、はじめに出会うのはたいていこの並びです。

EC2とECSは、何がちがう？

よく混ざる2つ。ボタンで切りかえて、自分の担当ぶんを見てみよう。

OSの入れかえや更新　自分

ピークに合わせて買うと、どうなる？

平常時とピーク時の台数を選んでみよう。単価は1台あたり月1万円と仮定、ピークは月の1割の時間だけとして計算します。

リクエストが1本、届いて返るまで

画面のボタンを押してから、答えが返るまでの5歩。タップして開いてみよう。

押してから、返ってくるまで

まちがえやすい3つ

ここを取りちがえると、話が噛み合わなくなります。

EC2とECSは、並べて選ぶものではない

EC2は借りたサーバーそのもの、ECSはコンテナをどこに何個置くかを決める係です。ECSの置き場としてEC2を使うこともあります。

「EC2にするかECSにするか」ではなく、「1台に自分で載せるか、箱にして置き方ごと任せるか」で考えると迷いません。

ELBは、ただの振り分け役ではない

振り分けと同時に、各台が生きているかを見張っています。返事をしない台は自動で外され、直れば戻されます。暗号化通信を入口で解く役も持てます。

「1台落ちても止まらない」は台数のおかげではなく、落ちた台を外してくれる見張りがいるおかげです。

RDSは「別のデータベース」ではない

中身は MySQL や PostgreSQL などのままです。ちがうのは、入れかえ・バックアップ・故障時の切りかえといった世話の部分を任せられるところ。

その代わり、機械に入って好きな設定ファイルを書く、といった自由は減ります。任せるとは、そういう取り引きです。

クイズ：きみは何問わかる？

全5問。まちがえても大丈夫、答えのほうが面白い。

気をつけないと、あとで困る

数分で借りられるということは、数分で事故も作れるということです。

  1. 1か所にまとめない。アプリの台もデータベースも、同じ建物（アベイラビリティゾーン）だけに置くと、その建物ごと落ちたときに全部止まります。最低でも2か所に分けます。
  2. 入口を開けっぱなしにしない。「とりあえず全部許可」で作ると、世界中から入れる状態になります。開けるのは必要な相手と必要な口だけにします。
  3. 権限は、最初から絞る。強い権限の鍵を配ると、漏れたときの被害が青天井になります。人にもプログラムにも、要る操作だけを許すのが基本です（IAM）。
  4. お金の見張りを付ける。借りたものは、使っていなくても動いていれば課金されます。上限の警告を設定し、消し忘れを定期的に探します。
  5. バックアップは、戻せて初めて意味がある。取れている、と思っていて戻せなかった例は珍しくありません。復旧の練習を一度やってから安心します。
  6. 名前と札を決めておく。誰が何のために作ったかわからない資源は、消すことも増やすこともできなくなります。命名とタグの規則を、増える前に決めます。

ことばのミニ辞典

この先どこかで見かけたときのために。

EC2
Elastic Compute Cloud。必要なときに借りられる仮想サーバー。OSから上は自分で面倒を見る、いちばん自由度の高い借り方。
ECS
Elastic Container Service。コンテナを「どこに何個動かすか」を決めて動かし続ける係。置き場としてEC2やFargateを使う。
ELB
Elastic Load Balancing。入口を1つに保ったまま、裏の台へアクセスを振り分けるしくみ。各台が生きているかも見張っている。
RDS
Relational Database Service。MySQLやPostgreSQLなどを、入れかえ・バックアップ・故障時の切りかえごと任せられる形で使えるサービス。
VPC
AWSの中に用意する、自分専用のネットワーク区画。どのアドレスを外に出し、どれを内側に隠すかを決める土地の区割りにあたる。
S3
ファイルを置いておくための保管庫。画像やログ、バックアップなど「そのまま置いておきたいもの」の置き場として使う。
IAM
誰が何をしてよいかを決めるしくみ。人にもプログラムにも鍵を配り、要る操作だけを許すのが基本の使い方。
リージョン／アベイラビリティゾーン（AZ）
リージョンは東京・大阪といった地域のまとまり。その中にある独立した建物のかたまりがAZで、2か所以上に分けて置くのが基本。
マネージドサービス
入れかえ・監視・バックアップといった世話をAWS側が引き受けてくれる形のサービス。自由度と引きかえに、手間を減らせる。
オートスケーリング
混み具合に応じて、台数を自動で増やしたり減らしたりするしくみ。ピークに合わせて常時そろえておく必要がなくなる。

ほかの解説ページ

  • MCPのしくみAIは、外の道具を借りて動いている。
  • CI/CDのしくみ直したものを、こわがらずに届けるために。
  • WebSocketのしくみ「まだ？」と聞きに行かなくてよくなった日。
  • Flywayのしくみデータベースだけ、やり直しがきかない。
  • Getdownのしくみ配ったあとに、直せるようにする。
  • Angularのしくみ画面を、部品に切り分ける。
  • BIG-IPのしくみ入口を1つにして、裏を何台にでも。
  • Springのしくみ部品の組み立てを、任せてしまう。
  • Dockerのしくみ「私のPCでは動く」を、なくすために。
  • Kubernetesのしくみ落ちたら、勝手に起き上がる。

AWS を、たとえ話・図解・クイズでたどるやさしい解説ページです。料金や設定の詳細は、公式ドキュメントをどうぞ。
