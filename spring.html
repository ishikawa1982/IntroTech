部品の組み立てを、
任せてしまう。

注文の処理を書きたいだけなのに、その前にデータベースの接続を用意して、設定を読み込んで、後始末を書いて……という準備が延々と続く。Spring は、その準備と組み立てを引き受ける係です。使う側は「これが要る」と書くだけでよくなります。

注文サービスが、動きだすまで——

  1. 「これが要る」と書くいま 注文の処理には、注文リポジトリが必要だと宣言する
  2. 起動時に
  3. Springが探す自動 目印のついたクラスを集めて、一覧を作る
  4. 順番を考えて
  5. 組み立てて渡す差し込む 必要なものを先に作り、それを渡しながら作っていく
  6. できあがると
  7. 使う側はnewしない差し替えできる テストのときだけ、偽物を渡すこともできる

やっていることは「誰が誰を必要としているかを、外側で管理する」。これが今日のいちばん大事なところ。

なんで、こんな道具が生まれたの？

答えはシンプル。自分で組み立てると、はがせなくなるから。

クラスの中で相手を作ると、固まる

注文処理のクラスの中に「本番用のデータベース接続を作る」と書いてしまうと、そのクラスは本番のデータベースなしでは動かせなくなります。

テストしたいだけなのにデータベースを立ち上げる必要がある。ここが、後になって効いてきます。

同じ準備を、毎回書いていた

接続を開く、設定を読む、トランザクションを始める、失敗したら戻す、最後に閉じる。やりたい処理は3行なのに、まわりの準備が30行。

しかも、その30行はどのクラスでもほぼ同じ。コピーされ、少しずつ書き方がずれ、閉じ忘れが混ざっていきます。

だから、組み立てを外に出す

「必要なものを、外から渡してもらう」形にする。これがDI（依存性の注入）。組み立て役をSpringに任せ、使う側は要求を書くだけにします。

渡すものを差し替えられるので、テストでは偽物を、本番では本物を、という切りかえが自然にできます。

SpringとSpring Bootのちがい

名前が2つあって、まずここでつまずきます。

Spring は、土台のほう

DIの仕組みそのものと、その上に積まれた機能群を指します。Web、データベース、認証など、目的ごとに部品が分かれています。

強力なぶん、使い始めるまでに決めることが多い。かつては設定ファイルとの格闘が名物でした。

Spring Boot は、初期設定つきの箱

「よくある構成なら、たいてい黙って動く」ようにしたもの。使いたい部品を宣言すると、それに合った初期設定が自動で入ります。

Webサーバーも中に入っているので、できあがったファイルを1つ実行すれば動く。今から始めるなら、まずこちらです。

アノテーションという目印

クラスやメソッドの上に付ける @ で始まる印です。「これはSpringが管理する部品」「ここはトランザクションの範囲」といった意味を、その場に書きます。

設定ファイルに書いていたことを、コードのそばに置けるようにしたもの。読みやすい反面、印の意味を知らないと動きが追えません。

クイズ：きみは何問わかる？

全5問。まちがえても大丈夫、答えのほうが面白い。

気をつけないと、追えなくなる

自動でやってくれることは、裏を返せば「見えない」ということです。

  1. 受け取り方は、コンストラクタで。必要なものを引数で受け取る形にしておくと、何に依存しているかが一目で分かります。フィールドに直接差し込む書き方は、依存が隠れます。
  2. 循環参照に気をつける。AがBを必要とし、BがAを必要とすると、組み立てられません。起動時に止まってくれますが、たいてい設計を見直す合図です。
  3. 自分のクラス内の呼び出しには、印が効かない。トランザクションなどの印は、外から呼ばれたときに働きます。同じクラス内のメソッドを直接呼ぶと素通りします。有名な落とし穴です。
  4. 設定を、コードに埋め込まない。接続先やパスワードは外部の設定に置き、環境ごとに切りかえます。これができていないと、環境が増えるたびにビルドし直すことになります。
  5. 印の意味を、調べてから使う。コピーしてきた @ が何をしているか分からないまま動かすと、不具合のときに手も足も出ません。
  6. 起動が遅くなることを見込む。部品を探して組み立てるぶん、立ち上がりに時間がかかります。開発中のやり直し回数を考えると、無視できない差になります。

ことばのミニ辞典

この先どこかで見かけたときのために。

DI（依存性の注入）
必要なものを自分で作らず、外から渡してもらう考え方。差し替えができるようになり、テストが書きやすくなる。
Bean
Springが管理している部品1つ1つのこと。目印を付けたクラスは、起動時に作られてBeanになる。
DIコンテナ
Beanを作って保管し、必要なところへ配る入れ物。Springの中心にある仕組み。
アノテーション
@ で始まる目印。クラスやメソッドに意味を持たせ、Springに扱い方を伝える。
AOP
本来の処理の前後に、共通の処理をはさみ込む仕組み。トランザクションやログの記録に使われる。
Spring Boot
よくある構成の初期設定をあらかじめ用意したもの。Webサーバーも同梱され、1つ実行すれば動く形にできる。

  • Angularのしくみ画面を、部品に切り分ける。
  • BIG-IPのしくみ入口を1つにして、裏を何台にでも。
  • Dockerのしくみ「私のPCでは動く」を、なくすために。
  • Kubernetesのしくみ落ちたら、勝手に起き上がる。
  • AWSのしくみサーバーを、買わずに借りる。
  • NoSQLのしくみ表の形に、こだわらない。
